\chapter{KESIMPULAN DAN SARAN}

\section{Kesimpulan}

Naskah ini telah merumuskan rancangan studi kasus komparatif terkontrol untuk membandingkan mode imperatif terotomasi berbasis \texttt{kubectl} dengan mode GitOps berbasis ArgoCD pada satu stack \textit{workload} multi-service InvenioRDM produksi-like. Rancangan membedakan kesetaraan konfigurasi dari kesehatan layanan, memisahkan waktu deteksi, ketersediaan bukti, dan pemulihan konfigurasi penuh, serta menetapkan mode imperatif sebagai penjedaan ArgoCD pada stack yang sama, bukan \textit{deployment} terpisah.

Kesimpulan empiris untuk setiap pertanyaan penelitian belum dapat ditarik:
\begin{enumerate}
  \item \textbf{RQ1:} Perbedaan kesetaraan konfigurasi dan kesehatan layanan belum diketahui karena data formal belum tersedia.
  \item \textbf{RQ2:} Perbedaan waktu deteksi, ketersediaan bukti penyimpangan, dan pemulihan konfigurasi belum diketahui. Tidak ada hasil waktu yang dapat diisi dengan asumsi atau angka sintetik.
\end{enumerate}

R3 (bukti keterlacakan) tidak diukur karena audit API server Kubernetes tidak tersedia. Ketiadaan audit tidak menghambat \textit{deployment} atau pengukuran R1/R2; R3 tidak dilaporkan sebagai nol atau tidak ada perbedaan. Dengan demikian, draf ini tidak menyimpulkan efektivitas, keunggulan, atau kelayakan adopsi salah satu mode. Skenario A sebagai kontrol HPA, F sebagai batas visibilitas, dan G sebagai kasus deskriptif bukan \textit{self-heal} ArgoCD harus dilaporkan terpisah, bukan sebagai bukti keberhasilan atau kegagalan rekonsiliasi.

\section{Saran}

Sebelum pengujian formal, protokol perlu ditinjau pembimbing, lalu apparatus harus divalidasi terhadap definisi penerimaan injeksi, skema inventaris dan bidang, keselamatan pencatatan Secret, interval sampling satu detik, timestamp, kriteria kesehatan, batas waktu, prosedur penjedaan/pemulihan ArgoCD, serta mekanisme reset. Sampel formal perlu dilaksanakan sesuai rencana 15 pengulangan per skenario per mode (10 R2 dan 5 R1; total 210 run) dengan pembekuan revisi sumber, SHA-256 render, image digest, dan versi runtime sebelum run pertama. Surrogat S1/S2 historis/offline tidak boleh menggantikan beban formal.

Pengumpulan data berikutnya sebaiknya mencatat konfigurasi serta versi yang benar-benar digunakan, mempertahankan semua kategori kegagalan dan penyensoran, melaporkan hasil per skenario, dan menyimpan bukti yang telah disanitasi. Klaim komparatif perlu dibatasi pada prosedur, \textit{workload}, klaster, dan resolusi instrumen yang diuji. Pekerjaan lanjutan dapat mengaktifkan audit API server untuk mengukur R3, menguji \textit{workload} atau ukuran klaster lain, serta membandingkan implementasi GitOps lain dengan definisi metrik yang sama.

\section{Keterbatasan Penelitian}

Keterbatasan yang melekat pada rancangan ini meliputi penggunaan satu klaster, satu stack InvenioRDM produksi-like, dan satu implementasi GitOps. Kedua mode dijalankan berurutan pada stack yang sama; tidak ada stack kembar \texttt{exp-*}, sehingga perlakuan tidak terisolasi dari beban latar, dependensi bersama, dan keadaan klaster yang berubah. Studi ini adalah studi kasus tunggal; hasilnya tidak otomatis berlaku bagi konteks lain.

Mode imperatif yang diuji adalah satu otomasi \texttt{kubectl} tertentu, sehingga tidak mewakili semua cara kerja imperatif. Interval sampling satu detik membatasi ketelitian waktu kejadian, dan target 210 run bukan jaminan daya statistik per skenario. Skenario A adalah kontrol HPA; F berada di luar cakupan sumber daya terkelola dan hanya menguji batas visibilitas; G adalah kasus deskriptif yang bukan \textit{self-heal} ArgoCD. Ketiganya tidak dipool ke estimasi efikasi B--E.

R3 tidak diukur karena audit API server Kubernetes tidak tersedia; tanpa audit, pelaku mutasi \textit{out-of-band} tidak dapat direkonstruksi. Pengukuran kesetaraan juga tidak menilai apakah konfigurasi yang diinginkan aman atau benar secara semantik. Selain itu, versi apparatus, inventaris formal, batas waktu pengamatan, serta kriteria kesehatan belum diverifikasi dalam draf ini. Protokol juga belum memperoleh tinjauan pembimbing dan kemampuan apparatus untuk menjalankannya belum divalidasi. Seluruh keterbatasan tersebut perlu dipertimbangkan sebelum hasil empiris tersedia atau rekomendasi praktis dirumuskan.
