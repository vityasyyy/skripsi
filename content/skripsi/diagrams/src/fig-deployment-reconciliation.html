Bab III: Rancangan perbandingan

Alur deployment dan rekonsiliasi apparatus

Deklarasi di Git diterapkan oleh ArgoCD, lalu keadaan live dipertahankan. Saat run berlangsung, mekanisme koreksi bergantung pada lengan yang aktif.

1. Deployment

Deklarasi menjadi workload
1

Commit deklarasi

Revisi dan render apparatus dibekukan di Git.

2

Render Kustomize

Application memilih kustomization dan menghasilkan objek.

3

Sync ArgoCD

Application controller mengirim state yang diinginkan.

4

Apply dan rollout

API server dan pengendali Kubernetes memperbarui workload.

5

Kesehatan

Status Synced dan Healthy diverifikasi sebelum run.

Deployment selesai sebelum run; status Synced dan Healthy menjadi gerbang kesiapan.

2. Rekonsiliasi

Drift kembali ke deklarasi
1

Drift out-of-band

Satu perubahan terkontrol terjadi di luar deklarasi.

2

Deteksi

ArgoCD membandingkan status, atau pemeriksa berjalan pada 5 s.

3

Perbaikan

Self-heal ArgoCD atau runbook kubectl yang tetap.

4

Verifikasi

Dua observasi cocok berurutan; waktu dilaporkan pada observasi pertama.

5

Reset dan cooldown

Baseline diverifikasi, lalu jeda 60 s sebelum sel berikutnya.

→
selama batch
Mode imperatif: auto-sync dan self-heal ArgoCD dijeda sebelum run, lalu dipulihkan pada blok finally dan diverifikasi. Mode GitOps: keduanya tetap aktif.
