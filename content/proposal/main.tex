\abstractind
Penelitian ini merancang studi kasus komparatif terkontrol atas dua mode pengelolaan pada satu stack InvenioRDM produksi-like: mode imperatif terotomasi berbasis \texttt{kubectl} dan mode GitOps berbasis ArgoCD. Pada mode imperatif, \textit{auto-sync}/\textit{self-heal} ArgoCD dijeda, pemeriksa dan \textit{runbook} otomatis menjalankan koreksi \texttt{kubectl}, lalu ArgoCD dipulihkan; ini bukan \textit{deployment} terpisah dan bukan studi waktu reaksi manusia. Kedua mode berjalan berurutan pada stack yang sama; tidak ada stack kembar \texttt{exp-*} dan tidak ada eksekusi paralel A/B, sehingga non-isolasi terhadap beban latar dan dependensi bersama menjadi keterbatasan eksplisit. Beban formal adalah InvenioRDM nyata dengan revisi sumber, render, image digest, dan versi runtime yang dibekukan. Tujuh skenario direncanakan. Skenario A adalah kontrol HPA dan \texttt{/spec/replicas} dikecualikan dari R1 statis; F adalah batas visibilitas objek tak terkelola; G adalah kasus deskriptif yang bukan \textit{self-heal} ArgoCD. A, F, dan G dipisahkan dari estimasi efikasi B--E. Metrik mencakup kesetaraan bidang konfigurasi (R1) serta waktu deteksi, ketersediaan bukti deviasi, dan pemulihan konfigurasi (R2); kesehatan dilaporkan terpisah. R3 tidak diukur karena audit API server tidak tersedia dan tidak dilaporkan sebagai nol atau tidak ada perbedaan. Sampel formal adalah $7 \times 2 \times 15 = 210$ run (10 R2 dan 5 R1 per sel) dengan sampling satu detik. Analisis mempertimbangkan uji nonparametrik berpasangan/blok, ukuran efek dan interval kepercayaan, serta penanganan tersensor kanan; studi ini adalah studi kasus tunggal sehingga validitas eksternalnya terbatas. Rancangan masih menunggu tinjauan dan belum ada data formal.

\vspace{0.5cm}
\noindent\textbf{Kata Kunci:} penyimpangan konfigurasi, Kubernetes, GitOps, prosedur imperatif terotomasi, studi kasus komparatif terkontrol
\endabstractind

\abstracteng
This proposal designs a controlled single-case comparative study of two management modes on one production-like InvenioRDM stack: an automated imperative mode based on kubectl and a GitOps mode based on ArgoCD. In the imperative mode, ArgoCD auto-sync/self-heal is paused, an automated checker and runbook perform kubectl corrections, and ArgoCD is then restored; this is not a separate deployment and not a human-reaction-time study. Both modes run sequentially on the same stack; there is no exp-* twin and no parallel A/B execution, so non-isolation from background load and shared dependencies is an explicit limitation. The formal workload is real InvenioRDM with a frozen source revision, render, image digests, and runtime versions. Seven scenarios are planned. Scenario A is an HPA control and /spec/replicas is excluded from static R1; F is a visibility boundary for unmanaged objects; G is a descriptive case that is not an ArgoCD self-heal case. A, F, and G are separated from efficacy estimates for B--E. Metrics cover selected-field configuration equality (R1) and detection, deviation-evidence availability, and configuration recovery times (R2); health is reported separately. R3 is not measured because Kubernetes API-server audit is unavailable and is not reported as zero or as no difference. The formal sample is 7 x 2 x 15 = 210 runs (10 R2 and 5 R1 per cell) with one-second sampling. Analysis considers paired/blocked nonparametric tests, effect sizes and confidence intervals, and explicit right-censoring; the study is a single case, so external validity is limited. Owner and supervisor review remains pending, and no formal dataset is available.

\vspace{0.5cm}
\noindent\textbf{Keywords:} configuration drift, Kubernetes, GitOps, automated imperative procedure, controlled single-case comparative study
\endabstracteng
