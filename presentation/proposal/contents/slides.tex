    \frametitle{Masalah Operasional: Configuration Drift}
    \vspace{0.25cm}
    \begin{columns}[T]
        \begin{column}{0.46\textwidth}
            \textbf{Drift terjadi ketika state aktual klaster menyimpang dari state yang dideklarasikan.}
            \begin{itemize}
                \item Perubahan langsung pada klaster tidak masuk ke Git.
                \item Prosedur manual berbeda antar eksekusi.
                \item Tidak ada mekanisme deteksi otomatis.
            \end{itemize}

% =============================================
% 6. Problem statement
% =============================================
{
\usebackgroundtemplate{\backgroundcontent}
\begin{frame}
    \frametitle{Rumusan Masalah}
    \vspace{0.35cm}
    \begin{beamercolorbox}[wd=\textwidth, sep=0.28cm, center, rounded=true]{structure}
        \large
        Sejauh mana paradigma manajemen deployment yang berbeda, yaitu pendekatan manual menggunakan \texttt{kubectl} dan pendekatan GitOps menggunakan ArgoCD, menghasilkan perbedaan pada karakteristik operasional ketika menghadapi \textit{configuration drift} yang terkontrol?
    \end{beamercolorbox}
    \vspace{0.35cm}
    \begin{enumerate}
        \item \textbf{R1 -- Konsistensi:} apakah deployment kembali sesuai dengan state yang diharapkan?
        \item \textbf{R2 -- Waktu:} berapa lama drift terdeteksi, dipulihkan, dan akar masalah diidentifikasi?
        \item \textbf{R3 -- Traceability:} seberapa lengkap perubahan dapat direkonstruksi?
    \end{enumerate}
\end{frame}
}
